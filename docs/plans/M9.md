- Parallel-safe with: none
- Notes: One module, `stop_lint`, registered twice in hooks.json: on SessionStart, where it records the
  starting state, and on Stop, where it compares, lints and blocks (PRAC-010). The block is
  `{"decision": "block", "reason": …}` on stdout, exit 0 (D-067, hooks reference). An app is linted only
  when it has `lint` and its files changed during the turn; changes from before the turn never count.
  Nothing blocks with no `.claude/casefile.json`, no app with `lint`, no change, a lint that times out
  or a lint whose tool is not on PATH (PRAC-012); in this task those cases print nothing — the report
  to the session is T4 (B3). Use `lib.config`, `lib.git_root`, `lib.app_folder`,
  `lib.app_touched`, `lib.command_tool` (T1); do not duplicate pre_commit's logic. Registration: no
  `onFailure` (it is not a guard; test_guards_fail_closed already requires that), a `timeout`, and
  `test_what_fires_where` gains both entries; update hooks.json's `description` to name the Stop lint.
  Standard library only (TOOL-004). PRAC-011's retry rule is T5 (B7). Reuse: tests/test_pre_commit.py `git`, `Repo.__init__`,
  `Repo.write`, `Repo.commit_all`, `stub_dir`, `with_real_path` — copy their pattern into
  tests/test_stop_lint.py (importing one test module from another is not set up in tests/).
  Planner choice: state is stored per session in the repository's git dir
  (`git rev-parse --git-dir`) at `casefile/stop-lint/<session_id>.json`; an event without `session_id`
  or outside a git repository does nothing. Planner choice: the state is `{"head": <HEAD sha>, "files":
  {<repo-relative path>: <git hash-object of its content, or null when deleted>}}` for every path
  `git status --porcelain -z --untracked-files=all` reports (ignored files excluded). A path changed
  during the turn when its current content (or absence) differs from its content in the state — the
  stored hash when it was dirty then, else its blob at the stored `head`; the paths compared are those
  dirty now, those dirty in the state, and `git diff --name-only <old head> HEAD`. Planner choice: the
  SessionStart entry has matcher `startup|resume|clear` and always rewrites the state; `compact` does
  not touch it. A Stop with no state for its session writes the state and lints nothing. The state is
  rewritten when the hook lets the turn end, never when it blocks (a blocked stop is not the end of the
  turn). Planner choice: the lint runs in the app's folder through the shell with a 240-second timeout,
  and the hook is registered with `timeout: 300`; apps are linted in config order, and every failing
  app's output goes into one reason: `casefile: the <app> lint fails (`<command>`). Last lines:` and the
  last 30 lines, as pre_commit does. Planner choice for the tests: the overlapping-name test has apps
  `web` (path `web`) and `webadmin` (path `webadmin`), changes only `webadmin/x.py`, and asserts only
  `webadmin`'s stub ran; the two-session test runs session `a` and session `b` on the same repository,
  changes a file after `a`'s turn ended, and asserts `b`'s first stop (state taken before the change)
  lints while `a`'s second stop compares with `a`'s own state; lint commands are `stub_dir` fakes
  (`fakelint`, exit 0 or 1) put on PATH; the timeout test patches the module's runner to raise
  `subprocess.TimeoutExpired`; the cannot-start test uses a tool missing from PATH.
