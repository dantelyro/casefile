# D-074 — casefile drops its multi-agent workflow; the main session does the work

**Status:** Accepted (2026-11-01).
**Decided by:** dantelyro — Grade 1: decided in session on 2026-11-01, in the developer's words quoted below

**Context:** A trial on 2026-11-01 built one Node CLI brief (tally: balances and minimum-transfer settle from a CSV) twice with casefile 0.28.1: in the main session, and through write-specs then implement with the planner, implementer and reviewer agents. Measured from the session transcripts and a hidden acceptance suite (Grade 1): the main session finished in 13 minutes, passed 15/15 acceptance tests and every edge-case probe, with 42k output tokens and 1.3M cache-read tokens. The agent run was stopped by the developer after 19 minutes at 2 of 14 tasks (about 4 minutes and one or two review rounds per task), having spent 96k output and 7.6M cache-read tokens. Its two worst flaws sat in its specs (an unterminated quote swallows the rest of the file, against the brief's every-invalid-line rule; an uncapped exponential settle), which a reviewer checking code against the specs cannot catch. In an earlier trial without casefile, one reviewer agent did catch real bugs the solo build had. D-071 had already recorded the developer finding the agents worse than the main session, and M7, M9, M10 and M11 were planned for the main session to build.

**Options:** (a) keep the agent workflow as it is; (b) the main session builds by default under the implementer's rules, and the reviewer agent runs once per milestone; (c) remove the multi-agent workflow entirely: the planner, implementer and reviewer agents and every reference to them, with the main session planning, building and checking the work.

**Decision:** (c), the developer's call: 'i will remove multiagents complelty from this and remove all references to it, its too expessive and takes to long the main session is enough for most tasks'. Earlier in the same session the developer set the condition for it: 'the main session need guidelines just as the subagents'. What gives the main session those guidelines, and which entries this supersedes, are settled when the change is specified; until it is built, the agents stay in the plugin and the entries that govern them stay in force.

**Trade-offs:** The independent review is given up: the one benefit an agent showed in the trials (a reviewer catching real bugs) has to come from the main session's own guidelines and checks instead. Guards that branch on agent_type (D-030, D-043) lose their subject. The removal is large: agents/, the dispatch in implement, fix-bug and review, the SubagentStart context (D-070), the guards and their tests, and specs 20 to 23. The evidence is one trial of one small task.
