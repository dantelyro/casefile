# D-076 — Code guidelines reach the main session through the SessionStart hook, as a third tagged block in session_start.py

**Status:** Accepted (2026-11-02).
**Decided by:** dantelyro — Grade 1: decided in session on 2026-11-02, in the developer's words quoted above

**Context:** This picks up the work D-066 (a code-practices skill, stack-scoped, for the main session and the agents) and D-067 (a Stop hook running the project's linter) planned and D-075 dropped unbuilt, saying it 'has to be specified again from nothing'; it is a new decision, not their revival. The developer wanted code guidelines (no magic numbers, no single-letter names, and the rest of their Code Practice Field Guide) loaded in every session. A plugin cannot ship instructions any other way: a CLAUDE.md at the plugin root is not loaded, .claude/rules/ belongs to the project, and InstructionsLoaded discards its output (hooks reference, fetched 2026-11-02; Grade 3). casefile's own code breaks these rules today: 86 single-letter assignments and 7 PLR2004 hits (ruff and grep, 2026-11-02; Grade 1), because the guide was never loaded or enforced here.

**Options:** (a) a Markdown file in shared/ that the hook reads; (b) a Markdown file beside the hook; (c) a GUIDELINES string in session_start.py beside CONTEXT and DIRECTIVE; (d) an output style with force-for-plugin; (e) a SubagentStart hook so every agent gets them too.

**Decision:** (c), the developer's call: 'i meant hte md file text in the py file', after (a) and (b) were built and moved. The block is tagged <casefile-guidelines> like the other two, and is given to the main session only: no agent gets it, so D-074 stands. The rules adopt the developer's own over the guide's N6: no single-letter names at all, loop variables included; magic numbers are a new rule. The guide's rule IDs were dropped from the text ('remove'), since they point at an artifact no session can open. Design rules (SOLID, adapters, folder layout, network timeouts) and domain-specific sections (DDD, events, APIs, React, web vitals, accessibility, observability) are left out because the text loads in every project with casefile installed, in the developer's words: 'repos can be very different so design has no place'. The developer added workflow rules: change only what was asked, report a bug found along the way and leave it, settle open questions before coding, check facts against current sources not memory, reuse existing code, propose a refactor and ask before it rather than work around, keep libraries that reach outside the program behind an interface, build test-first, keep tests isolated, treat existing tests as business rules and ask before changing or deleting one, and run the tests and reproduce a bug before fixing it.

**Trade-offs:** Every session of every project with casefile pays for about 40 more lines, and gets this developer's style whether it wants it or not; a casefile.json switch is not built. Text asks, it does not enforce: the rules a linter can check (PLR2004, N, a single-letter check ruff lacks) are still to be turned on, with a rename of the existing code first. The reviewer does not get the guidelines yet.
